# 17: A drop-mode switch on every category, and a Raw materials category

Status: ready-for-agent

**Recommended model:** `opus`: settings move from old keys to new ones, and a mistake would silently lose players' or packs' saved choices.

**Blocked by:** None (can start immediately)

**What to build:** Replace the two drop-mode exemption settings with one "Include in drop mode" switch on each category rule, and add Raw materials as an inventory category. Source of truth: the spec's "Which categories the drop mode judges" and "Raw materials" paragraphs, and the decision rows "Drop mode scope", "Raw materials category", "Materials and eras" and "Scrap amount for stacks" (all settled 2026-11-24). Do not redesign them. The era-less stuff rule in `EraReader.ItemEra` and the per-stack scrap rounding in `ItemClassifier.ScrapUnits` / `ScrapAmounts.StackUnits` are already in the working tree; build on them.

## Scope

**Rule field and evaluator**
- `Source/Model/LootRules.cs`: add `public bool inDropMode;` to `CategoryRule`; add `public CategoryRule rawMaterials = new CategoryRule(Outcome.Keep);`; delete `dropIncludesMedicine` and `dropIncludesAmmunition`. Saved key follows `SettingKeys.KeyFor`: `rules.medicine.inDropMode` is saved as `medicineInDropMode`. Lock path `rules.<category>.inDropMode`; the whole-category lock `rules.<category>` already copies it (`ValueWalk.CopyPath`).
- Defaults: `inDropMode` true for weapons and apparel, false for ammunition, drugs, medicine, food, rawMaterials and other. Set in the field initialisers, `Source/Model/Presets.cs` (both places that set the old fields, lines ~91 and ~130; Progression, Cleanup, Vanilla all the same), and `Defs/SettingsDefaults.xml`. The test that the shipped XML equals the compiled Progression preset must pass.
- `Source/Model/LootEvaluator.cs` `ApplyDropMode`: replace the two category checks with `if (!(rules.RuleFor(item.Category)?.inDropMode ?? false)) return null;` before the mode switch, for every drop mode. A weapon or apparel carried in the inventory counts as gear: `InventoryCategoryOf` must classify by `EraReader.IsGear(def)` first and return Weapon or Apparel (check how `GearSorter` and `ItemClassifier` classify worn and carried gear today and make carried gear take the gear categories, so its switch is the weapon or apparel one).

**Raw materials category**
- `Source/Model/DropCandidate.cs` `ItemCategory`: add `RawMaterials`. `Source/Model/ItemCategories.cs`: add the row (field `rawMaterials`, label key `LootScavenging_CategoryRawMaterials`), placed before Other so it follows page order. Lock name and saved keys come from the table.
- `Source/Loot/ItemClassifier.InventoryCategoryOf`: check order is gear (Weapon/Apparel), ammunition, medicine, drugs, food, then raw materials, then other. Raw materials comes after food so a medicine, drug or meal that is also stuff or filed under raw resources keeps its own category (survival meals and go-juice stay food and drugs); it comes before Other. A thing is raw materials when `def.IsStuff` (and not gear), or any of its `thingCategories` or their parents is `ResourcesRaw`.
- Verified in the game's Core defs (`Defs/ThingCategoryDefs/ThingCategories.xml`): `ResourcesRaw` has children `PlantMatter` and `StoneBlocks` only. Components, chemfuel and neutroamine are filed under `Manufactured`, not `ResourcesRaw`, and are not stuff, yet the spec lists them as raw materials. Resolve it by also matching the `Manufactured` category tree (excluding anything already caught by the earlier checks, and excluding `MortarShells` and its children, which are ammunition-like). Dump the matched defs for Core (and Royalty, Ideology, Biotech, Anomaly if installed) once while building, confirm components, chemfuel, neutroamine, steel, plasteel, wood, stone blocks, silver, gold, devilstrand and cloth land in Raw materials, and note any surprise in the ticket comments. Note this in the spec's raw materials paragraph if the implementation differs from its wording.
- Check that `Scrap everything` with the switch on turns a no-era stack into scrap of the colony's era (`ItemEra` returns an era-less result for stuff; the scrap era for no-era items must resolve to the colony era, not fail or use the fallback setting). Fix if not.

**Moving the old settings (must lose nothing)**
- `Source/LootScavengingSettings.cs` / `Source/Model/SettingsLoad.cs`: when a saved file contains `dropIncludesMedicine` or `dropIncludesAmmunition`, read each once and set `rules.medicine.inDropMode` / `rules.ammunition.inDropMode` from it, unless the file already has the new key. Record the legacy keys among the loaded keys so `FillMissing` does not overwrite them. A file that lacks the old key (the save omits values equal to the default, so a false value is absent) takes the new baseline, which is off: same result. Keys the file lacks for the new fields (`weaponsInDropMode`, `rawMaterialsOutcome`, and so on) fill from the baseline, so an old config gets weapons and apparel on and raw materials Keep. The old keys are never written again.
- Packs: `Source/SettingsDefaultsDef.cs` and `Defs/SettingsDefaults.xml`. A pack's `<locked>` list may name `rules.dropIncludesMedicine` or `rules.dropIncludesAmmunition`; treat these as aliases of `rules.medicine.inDropMode` and `rules.ammunition.inDropMode` (accept them in `SettingLocks` without reporting them as unknown, and map them to the new names), so the lock holds. Add `rules.<category>.inDropMode` to `SettingLocks.Lockable` for every category (one row each, shown disabled when locked), and remove the two old `SettingNames` constants. A pack's patched `<values><rules>` that still sets `<dropIncludesMedicine>` or `<dropIncludesAmmunition>` must load without error and move to the new field the same way (keep a small legacy read for the Def, since the XML loader would otherwise warn about an unknown field). Update the header comment of `Defs/SettingsDefaults.xml` (lockable list, new fields) and check `packs/progression/` for the old names.
- `Source/Model/Presets.cs` preset building and Reset keep applying locks as before; `ShippedDefaultsTests` still equal.
